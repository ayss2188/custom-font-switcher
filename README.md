## 一、详细介绍

### 1. 核心理念：你的字体，你做主

本模块**不内置任何字体**，刷入后默认「无字体」，不改动系统任何东西。你可以在 WebUI 里导入自己喜欢的 TTF / OTF 字体（可多选），点一下卡片就能切换，重启生效；选「无字体」即恢复系统默认。

五个设计选择：

1. **不内置任何字体**：刷机包只有几十 KB，没有版权风险，字体完全由你决定；
2. **自带挂载**：Magisk / KernelSU / SukiSU / APatch 通用，KernelSU 系不需要元模块；
3. **按本机真实槽位替换**：不拿固定清单硬铺，不同 ROM、不同版本都只动真实存在的文件；
4. **切换是原子的**：先生成、再校验、最后提交，中途失败保留原来的字体；
5. **全程可逆**：只读挂载、不改系统分区、不改字体配置 XML，禁用模块即恢复，卸载连字体库一起清掉。

此外：

- **字体库**：所有导入的字体集中存放在 `/data/adb/custom_font_lib`，更新模块不会丢失；
- **可变字体友好**：导入可变字体（Variable Font）时，系统调节字重会在 wght 轴上平滑过渡；静态字体则各字重外观相同；
- **覆盖范围识别**：导入时自动读取字体的字符覆盖范围，判断是「中英文」「仅英文 / 数字」还是「仅中文」，并据此决定替换哪些字体槽，避免英文字体把中文换成方块；
- **一键体检**：在 WebUI 里点「查看诊断报告」，或点模块卡片上的「操作」按钮，即可生成一份**结论优先**的完整报告（含实际生效的字体目录、字体配置原文、每个字体的 sha256、挂载实测与开机日志）；生成过程可以看到进度、预计剩余时间，随时中止、随时关窗口，**生成完会自动保存**（不用再点保存），反馈问题时发这一份文件就够了。

### 2. 核心机制

#### 2.1 自带挂载：bind mount，而不是「替换系统文件」

传统字体模块要么把字体写进 `/system` 之类的分区（动只读分区，风险高、不可逆），要么依赖 Hybrid Mount 这类元模块帮忙挂载。本模块走的是 bind mount：

- **原理**：把字体库里的字体文件绑定挂载到每个真实存在的字体槽路径上。系统读取 `/system/fonts/xxx.ttf` 时读到的是字体库里的文件，物理分区一个字节都没改；
- **只读**：挂载后立即 `remount,bind,ro`，运行期不可写；
- **零重复占用**：所有槽位都指向字体库里同一个文件，替换一百个槽位也只占一份字体的空间；
- **重启即还原**：挂载只存在于内存，重启自动消失，不存在残留。

挂载时机：

- **Magisk**：post-fs-data 阶段挂载（Magisk 没有 post-mount 阶段）；
- **KernelSU / SukiSU / APatch**：post-mount 阶段挂载，排在元模块和其他模块之后，避免被别人的目录级挂载盖住；
- 模块自带 `skip_mount` 标记，管理器不会再多挂一次；
- 覆盖 `my_product`、`mi_ext` 等厂商分区里的字体槽，这些分区很多元模块并不支持。

个别环境自带挂载不工作时，可在设置里切回「交给管理器挂载」（传统方式）。

#### 2.2 槽位发现：为什么不用固定清单

不同系统的字体槽数量差异很大：HyperOS 有几十个，ColorOS 上百个，OriginOS / Flyme / 原生各不相同，同一系统升级后还会变。固定清单要么漏槽（部分界面没变、字体混搭），要么乱铺。本模块的做法是「实时勘探 + 白名单过滤」：

1. 候选槽位来自三方面：系统字体配置 XML 中的主文字族、各系统验证过的已知文件名（内置 HyperOS / ColorOS / OriginOS / Flyme / AOSP 五套）、厂商命名规则扫描；
2. 只替换手机上真实存在的字体文件，不凭空创建不存在的路径；
3. 扫描 20 多个已知字体目录，并自动发现未知厂商分区（`/xxx/fonts`），不依赖机型白名单，排除符号链接与系统目录避免重复；
4. **默认不碰**日韩及其他文字、符号 / Emoji、衬线 / 等宽 / 时钟 / 展示 / 斜体等高风险槽位，避免锁屏时钟、终端、表情变成方块（可在设置里关闭「保留」开关）。

支持的系统：

- 小米系：澎湃OS / HyperOS / MIUI（小米 / 红米 / POCO）
- OPPO 系：ColorOS（OPPO / 一加 / realme）
- vivo 系：OriginOS（vivo / iQOO）
- 魅族：Flyme
- 三星 One UI、荣耀 MagicOS、华为 EMUI / 鸿蒙（AOSP 兼容版）、Nothing OS（通用适配）
- 原生 / 类原生 / Pixel / GSI：兜底通用适配

刷入后 `module.prop` 描述会显示「识别到的系统」和「当前生效的字体」。

#### 2.3 切换是原子的

字体切换最怕「改一半」。所以切换严格分三步，任何一步失败都不会破坏当前生效的字体：

1. **生成**：先把要用的字体文件准备到临时暂存目录。自带挂载模式只记录「槽位 → 字体」的映射，模块目录里不留副本；管理器模式优先用硬链接，同样不额外占空间；
2. **校验**：需要复制的文件逐字节比对大小，槽位数为 0 或任何一步出错立即中止；
3. **提交**：最后一步才把新的映射表和清单整体替换上去。

失败时会提示「生成字体文件失败（存储空间不足？），已保留原来的字体」。字体文件同时会被设为 644 权限和 SELinux 的 `system_file` 上下文。

#### 2.4 生效是「实测」的

「实际挂载 / 实际生效检测」是真的去比对文件身份，而不是界面显示切了就算：

- 自带挂载模式下，目标就是 bind mount 过来的同一个文件，设备号:inode 必然与字体库里的源文件一致，一致才算生效；
- 交给管理器挂载时（会经过 overlay / tmpfs，inode 不同），自动退化为逐文件大小比对；
- 每次开机的挂载结果（成功 / 失败 / 跳过多少个）都会记录，WebUI 直接显示；若本次开机没有执行自带挂载，页面会提示，诊断报告里会说明原因（多为管理器不支持 post-mount）。

#### 2.5 开机保护

选完字体后的第一次重启最危险。模块的做法：

- 选字体后写一个 `.booting` 哨兵；
- 下次开机时若哨兵还在（说明上一次没走到开机完成），自动撤销全部字体文件、清空映射表、把选择恢复成「无字体」，并留下 `rescued` 标记，WebUI 会提示「上次开机失败，已自动恢复」；
- 只有真的选过字体才会看守，平时开机开销为零。

这是尽力而为的保护：极端情况（卡在系统启动完成之前）可能还需要再重启一次才能恢复。这也是模块默认保持「无字体」、并且从不修改系统分区的原因。

#### 2.6 一键体检（诊断报告）

模块自带自检：**在 WebUI 里点「查看诊断报告」，或点模块卡片的「操作」按钮**才会跑（安装阶段不做任何耗时收集，避免刷入卡住）。

点开时先是「快速体检 / 完整报告」两个按钮，并**按本机实际字体数量算出预计耗时**（例如"快速体检 1 分 10 秒 ~ 2 分 40 秒；完整报告 3 分 ~ 7 分"，字体越多越久）。快速体检只算必要字体的指纹（推荐）；完整报告所有字体都算指纹，读盘更多、更慢。

生成时：显示**第 N/6 步 + 进度条 + 百分比 + 已用时间 + 预计剩余时间**，**结论一写完就先显示出来**（不用等全部跑完），可以**随时中止**，也可以**关掉窗口让它在后台继续**（再打开是接着看，不会白跑一遍）。

> 为了不卡手机，生成任务会主动降到最低优先级（CPU nice 19 + 磁盘 idle）并定期让出资源，所以比"全速跑"慢一些 —— 这是故意的：宁可慢一点，也不要让你点什么都点不动。

报告是**结论优先**的：

- **结论**：模块是否被禁用 / 待卸载 / 尚未激活、是否处于安全模式、是否与 Magisk 共存、本次开机的 `post-fs-data` 与 `service` 有没有被执行、挂载能不能成功；
- **实机挂载实测**：现场取一个真实槽位做 bind 挂载、校验 `设备号:inode`、随即卸载还原——能不能挂当场就有结论，失败会带出真实报错；
- **槽位与配置**：候选槽位明细、当前替换计划、被「保留」的槽位、设备上全部字体目录清单，以及系统字体配置（fonts.xml / fonts_additional / font_fallback / fonts_customization 与分区、apex 下的）中 sans-serif 族与中文族的原文、配置引用的文件是否存在、所有 `.ttc` 合集及其 face 个数；
- **实际生效的字体目录（精准适配的关键）**：每个字体目录的真实路径与 `dev:ino`（识别符号链接、判断两个目录是不是同一份）、配置里每个字体名按 Android 规则解析后**框架真正会读的路径**、同名文件在别的目录里的**独立副本**，以及替换计划分别落在哪些目录；
- **字体来源排查**：字体包（flipfont）、`/data/fonts` 可更新字体、**MIUI / HyperOS 个性字体（主题字体，含与系统同名的那些）**、**厂商「个性化字体」**（如魅族 `/data/customizecenter/font/flymeFont.ttf`，优先级高于 `/system/fonts`）、主题 overlay、设备上已装的字体相关设置——排查「换了字体却没用」；
- **字体指纹**：字体库里每个文件的 sha256、大小、sfnt 表信息（可判断可变字体）；
- **开机痕迹与日志**：每次开机 `post-fs-data` / `service` 的执行记录（`/data/adb/custom_font_lib/boot_events.log`）、挂载失败的真实报错（`mount.log`）、KernelSU 日志与内核信息。

点「查看诊断报告」并生成完就会**自动保存**（完整报告连同**原始字体配置文件和系统字体完整清单**一起写在同一个 txt 里）：

- 快速体检 → `Download/快速体检报告.txt`
- 完整报告 → `Download/完整体检报告.txt`
- 生成中途（可以随时拿走）→ `Download/未完成的体检报告.txt`
- 另有一份固定名 `Download/font_diag.txt`，内容 = 最近生成的那一份

遇到问题把其中一个文件发出来，作者就有足够的数据定位，不用来回问。报告最后还附有**每一步耗时**，慢在哪一步一眼可见。

报告是在**后台生成**的：点开弹窗后可以随便关掉，生成完再点一次就能看到；界面不会因为生成报告而卡住。

### 3. 谷歌字体兼容

Chrome、Gmail 等 Google 应用的英文数字，会在 GMS 的 FontsProvider 下载官方 Google Sans 之后变回默认。本模块内置「谷歌字体兼容」开关（WebUI 内操作）：

- **做法**：仅停用 GMS 的 `com.google.android.gms.fonts.provider.FontsProvider` 组件，不卸载、不清数据、不动账户；随后结束 GMS 与谷歌商店进程，让已缓存的下载字体失效；
- **效果**：Chrome、Gmail 等应用的英文数字回退到系统字体（即你选的字体），立即生效，无需重启；
- **可逆**：随时一键「关闭兼容」；卸载模块时自动恢复，且只恢复本模块自己停用过的组件（记录在字体库的 `.gms_owned`），你本来就手动停用过的不会被越权改动。

### 4. GitHub 在线更新

- WebUI 里可以**检查更新、查看更新日志、一键下载并安装**，不用再去网盘找新版；
- **每次打开 WebUI 都会自动检查一次更新**（右上角也会显示上次检查的结果），不会再出现「管理器提示有更新、WebUI 里看不到」的情况；
- 先校验再安装：校验 sha256（发布时由 GitHub Actions 自动写入）和包内模块 ID，任何一项不符都不会安装；
- 下载安装完成后，「下载并安装」按钮会变成红色的 **「立即重启生效」**，点它直接重启；刷新页面也会保持这个状态，直到重启完成；
- Magisk / KernelSU / APatch 管理器的模块列表也会显示「有更新」；
- 更新 / 覆盖安装**不会清空字体库和设置**，重启后自动恢复你上次选的字体。

### 5. 安全、隐私与卸载

- **权限与网络**：只做挂载和字体文件管理；除「检查更新」外不联网，不收集、不上报任何信息；
- **系统分区**：只读挂载，绝不写入；不修改 `fonts.xml` 等字体配置；
- **冲突检测**：发现同时启用了其他字体模块，会在安装界面、WebUI 和模块描述里提醒；
- **卸载**：在管理器中禁用模块即停止全部替换；点「卸载」会恢复本模块停用过的谷歌组件，并删除字体库 `/data/adb/custom_font_lib`。

### 💡 已知局限

- **谷歌商店（Play Store）**：新版把 Google Sans 直接打包进了 APK，属于「应用内置字体」，任何系统级字体模块都无法替换，Chrome / Gmail 生效、商店不变属正常现象；
- **QQ、微信等个别页面**：走独立的渲染逻辑或自带字体，不会随系统改变；
- **游戏、阅读器、网页 CSS 字体、图片文字**：不经过系统字体，不受影响；
- **魅族个性化字体**：Flyme 另有 `/data/customizecenter/font` 字体机制，本模块只覆盖系统字体链路；
- **TTC 合集**：不能直接导入，请先用 `tools/optimize_font.py --face 0` 取出单个字体（电脑或手机 Termux 均可，见第六节）；
- **部分厂商 ROM 的非标准字体槽**：欢迎附诊断报告反馈，会按报告补进内置清单。

## 二、刷前准备与避坑指南（必看！）

- **Root 权限环境**：支持 Magisk（v20.4+）/ KernelSU / APatch。
- **不需要元模块**：模块自带挂载，KernelSU / APatch 用户无需先装 Hybrid Mount 等元模块。
- **KernelSU / APatch 用户建议关闭「默认卸载模块」**：打开管理器设置，找到【默认卸载模块】并关闭，避免部分应用被隔离后看到的是系统默认字体。
- **停用其他字体模块**：多个字体模块会互相覆盖，刷入前请先停用。
- **Magisk 用户**：Magisk 没有 WebUI 入口，需要安装 [KsuWebUI](https://github.com/5ec1cff/KsuWebUIStandalone)（或 WebUI X）来打开管理界面。

## 三、关键设置：解决「部分生效 / 没完全变」问题

### 小米 / 澎湃系统

本模块是**直接按目标文件 bind 挂载**（并且会按系统字体配置解析出框架真正读取的路径），一般刷入重启即可，不需要再手动切一次字体。

只有一种情况需要你动一下手：**手机上设置过「个性字体 / 主题字体」**。

- **现象**：重启后有的地方变了、有的地方没变（例如设置界面变了但桌面没变），或者干脆没变；
- **原因**：MIUI / HyperOS 的个性字体会放在 `/data/system/theme/fonts/` 之类的目录里，由主题机制接管，优先级高于 `/system/fonts`，甚至会顶替同名的系统字体；
- **确认方法**：打开 WebUI ➔「查看诊断报告」，看**第 7 节（字体来源排查）**里"MIUI / HyperOS 个性字体"那一段——如果列出了与系统同名的字体，就是它在接管；
- **解决方法**：
  1. 打开手机 **设置 ➔ 显示 ➔ 字体大小和样式**（不同版本叫「系统个性化 ➔ 字体」）；
  2. 把字体切成 **默认**（或【小米兰亭Pro】）；
  3. 重启一次，本模块的替换就会全面生效。

> 该步骤仅 MIUI / HyperOS 需要。ColorOS、OriginOS、原生系统一般刷入重启即可。

### 魅族 / Flyme

魅族也有一套「个性化字体」机制，和 MIUI 类似但路径不同：

- **现象**：刷入本模块并重启后**完全没有变化**（不是"有的地方变了"，而是整个界面都没变）；
- **原因**：Flyme 把用户选的字体放在 `/data/customizecenter/font/flymeFont.ttf`，**优先级高于 `/system/fonts`** —— 只替换系统字体文件的话，系统根本不读那些文件；
- **确认方法**：打开 WebUI ➔「查看诊断报告」，**结论区会直接列出这个文件**（大小 / 修改时间 / 指纹），第 7 节还会单独列一段「厂商个性化字体」；
- **本模块目前的处理：只检测、不接管**（真机上没验证过的路径不默认去改）。所以有两种做法：
  1. **现在就想换字体**：用文件管理器把自己的字体**改名成 `flymeFont.ttf`** 覆盖进去，重启即可（这个位置在 `/data` 上，**不需要 root**）。诊断报告可以用来看有没有替换成功（对比修改时间和指纹）。
  2. **想让模块以后也接管它**：把「查看诊断报告」生成的报告发出来，作者会先看这台机器的实际情况（挂载点、权限、校验方式），确认安全后再加适配。

### 其他排查

1. 打开 WebUI，看状态栏「实际挂载」是否显示成功；
2. 点「查看诊断报告」，看「实际生效检测」是否接近已替换的槽位数；
3. 如果提示「本次开机没有执行自带挂载」，在设置里改为「交给管理器挂载」后重新选字体、重启；
4. 仍然不行，把「查看诊断报告」生成的报告附在 Issue 里反馈——报告是结论优先的，里面已经包含判断结论、槽位明细、系统字体配置原文、字体指纹、每一步耗时与日志，不用再额外提供别的东西。

## 四、详细刷入与使用教程

### 1. KernelSU / APatch

1. 打开管理器，进入【模块】页面，点击「从存储安装」，选中下载好的 `custom-font-switcher.zip`；
2. 刷入完成后重启手机；

## 五、WebUI 状态与生效说明

由于系统机制限制，切换字体后不会自动重启，页面上提供了状态提示：

- **当前实际生效**：此时此刻系统正在使用的字体；
- **待生效（下次重启后）**：你刚点选、已生成好的新字体；
- **已替换槽位 / 实际挂载**：本次替换了多少个字体槽、开机时成功挂载了多少个。

生效方法：选好字体后，点击页面底部的「立即重启生效」，或自行手动重启手机。

**高级设置**：

- 保留日韩及其他文字的字体槽（推荐开启）；
- 保留衬线 / 等宽 / 时钟 / 展示 / 斜体槽（推荐开启）；
- 模块自带挂载（推荐开启）。

修改设置后会按当前选择自动重新生成，重启生效。WebUI 支持深浅色跟随系统、主题切换与过渡动画。

## 六、字体精简工具（可选，电脑或手机均可）

体积很大的字体（几十 MB）会占用更多内存、首次加载更慢。刷机包 `tools/optimize_font.py` 可以精简字体、把可变字体转成静态、从 TTC 合集里取出单个字体。

**电脑上：**

```sh
pip install fonttools
python optimize_font.py 原字体.ttf -o 精简后.ttf --family "My Sans"
python optimize_font.py 原字体.ttf -o out.ttf --wght 400        # 可变字体转静态
python optimize_font.py 合集.ttc -o out.ttf --face 0            # 从 TTC 合集取出单个字体
```

**手机上（Termux）：**

1. 安装 Termux，执行 `pkg install python`，再执行 `pip install fonttools`；
2. 把刷机包 zip 里的 `tools/optimize_font.py`，以及要处理的字体放到手机存储里（如 Download 目录）；
3. 先执行一次 `termux-setup-storage` 授权存储，然后：

```sh
cd ~/storage/downloads
python optimize_font.py 原字体.ttf -o 精简后.ttf --family "My Sans"
```

精简后的文件回到模块 WebUI 里导入即可。手机处理几十 MB 的字体会比电脑慢不少，并且比较吃内存，处理时请保持 Termux 在前台。

默认保留拉丁 / 标点 / 假名 + GB2312 简体 + Big5 常用繁体（约 1.2 万字），冷门字会回退到系统字体。
