【自定义字体切换模块 v1.0】导入你自己的字体，全局一键替换

「换字体」这件事，老玩家多少都踩过同样的坑：模块内置的字体不是自己想要的；好不容易找到喜欢的字体，刷进去却发现只有一半界面变了；在 KernelSU / APatch 上还得先装个元模块、多重启一次；想换回系统默认，只能卸载重刷。

这个模块想解决的就是这三件事：不内置字体（你自己带）、不需要元模块（它自己挂载）、按本机真实字体槽替换（该变的地方都变）。刷入后默认处于「无字体」状态，不改动系统任何东西；导入你的 TTF / OTF，点一下卡片，重启，全局生效。

一、它凭什么和别人不一样：五个设计选择

1. 不内置任何字体 —— 体积只有几十 KB，没有版权风险，字体完全由你决定；
2. 自带挂载 —— Magisk / KernelSU / SukiSU / APatch 通用，KSU 系不需要元模块；
3. 按本机真实槽位替换 —— 不拿固定清单硬铺，不同 ROM、不同版本都只动真实存在的文件；
4. 切换是原子的 —— 先生成、再校验、最后提交，中途失败保留原来的字体；
5. 全程可逆 —— 只读挂载、不改系统分区、不改字体配置 XML，禁用模块即恢复，卸载连字体库一起清掉。

下面把「怎么做到的」讲清楚。只想装机的机友可以直接跳到第四节。

二、核心机制详解

2.1 自带挂载：bind mount，而不是「替换系统文件」

传统字体模块通常两条路：要么把字体真的写进 /system 之类分区（动只读分区，风险高、不可逆），要么依赖 Hybrid Mount 这类元模块帮忙挂载。

本模块走的是 bind mount：

- 原理：把字体库里的字体文件，绑定挂载到每一个真实存在的字体槽路径上。系统去读 /system/fonts/xxx.ttf 时，读到的其实是字体库里的文件，物理分区一个字节都没改；
- 只读：挂载后立即 remount,bind,ro，运行期不可写；
- 零重复占用：所有槽位都指向字体库里同一个文件，替换一百个槽位也只占一份字体的空间；
- 重启即还原：挂载只存在于内存，重启自动消失，不存在残留。

挂载时机是刻意设计的：

- Magisk：在 post-fs-data 阶段挂载（Magisk 没有 post-mount 阶段）；
- KernelSU / SukiSU / APatch：在 post-mount 阶段挂载 —— 排在元模块和其他模块的挂载之后，避免被别人的目录级挂载盖住；
- 模块自带 skip_mount 标记，管理器不会再多挂一次；
- 覆盖范围包含 my_product、mi_ext、oplus_product、vivo、prism 等厂商分区 —— 这些分区里的字体槽，很多元模块并不支持。

个别环境自带挂载不工作，也可以在设置里一键切回「交给管理器挂载」（传统方式）。

2.2 槽位发现：为什么不用固定清单

固定清单的死穴是系统差异太大：HyperOS 的字体槽有几十个，ColorOS 上百个，OriginOS / Flyme / 原生各不相同，同一系统升级后还会变。固定清单要么漏槽（部分界面没变、字体混搭），要么乱铺（凭空创建一堆不存在的挂载点）。

本模块的做法是「实时勘探 + 白名单过滤」：

- 候选来源三条：系统字体配置 XML（fonts.xml 等）里的主文字族 ∪ 本 ROM 已验证的字体槽清单（内置 5 套：HyperOS / ColorOS / OriginOS / Flyme / AOSP）∪ 厂商命名规则；
- 只替换设备上真实存在的字体文件，绝不凭空创建路径 —— 挂载节点更少，风险更低；
- 扫描 20 多个已知字体目录，并自动发现未知厂商分区（/xxx/fonts、/xxx/yyy/fonts），排除符号链接与系统目录，避免重复；
- 高风险槽位默认不动：其他文字体系（日韩等）、符号 / Emoji、衬线、等宽、时钟、展示、斜体 —— 避免锁屏时钟、终端、表情变成方块；
- 想全都要：到「替换范围（高级）」里关掉对应的「保留」开关即可。

2.3 切换是原子的：先生成、再校验、最后提交

字体切换最怕「改一半」：一部分槽位指向新字体、一部分还是旧的，甚至文件损坏。

所以切换严格分三步，任何一步失败都不会破坏当前生效的字体：

1. 生成：先把所有要用的字体文件准备到一个临时暂存目录。自带挂载模式只需要记录「槽位 → 字体」的映射，模块目录里不留任何副本；管理器模式优先用硬链接，同样不额外占空间；
2. 校验：需要复制的文件必须完整（逐字节大小比对），槽位数为 0 或任何一步出错就立即中止；
3. 提交：最后一步才把新的映射表和清单整体替换上去。

失败时会明确告诉你「生成字体文件失败（存储空间不足？），已保留原来的字体」——当前字体不会被破坏。字体文件同时会被设上 644 权限和 SELinux 的 system_file 上下文，避免权限与策略问题。

2.4 生效是「实测」的，不是「界面显示切了」

不少模块的通病：界面显示已切换，实际没生效。本模块的「实际挂载 / 实际生效检测」是真的去比对文件身份：

- 自带挂载模式下，目标就是 bind mount 过来的同一个文件，它的设备号:inode 必然与字体库里的源文件完全一致 —— 一致才算生效；
- 交给管理器挂载时（会经过 overlay / tmpfs，inode 必然不同），自动退化为逐文件大小比对；
- 每次开机的挂载结果（成功 / 失败 / 跳过多少个）都会记录，WebUI 直接显示；若本次开机没有执行自带挂载，页面会提示你，并在诊断报告里说明原因（多为管理器不支持 post-mount）。

2.5 开机保护：把「卡开机」的可能性降到最低

选完字体的第一次重启是最危险的时刻。模块的做法：

- 选字体后写一个 .booting 哨兵；
- 下次开机时若哨兵还在（说明上一次没走到系统启动完成），自动撤销全部字体文件、清空映射表、把选择恢复成「无字体」，并留下 rescued 标记，WebUI 会提示「上次开机失败，已自动恢复」；
- 只有真的选过字体才会看守，平时开机的开销为零。

需要如实说明：这是尽力而为的保护 —— 极端情况（卡在系统启动完成之前）可能还需要你再重启一次才能恢复。这也是模块默认保持「无字体」、并且从不修改系统分区的原因。

2.6 字体「体检」：中英文范围自动识别

导入时读取字体的字符覆盖范围，自动判断它是「中英文」「仅英文 / 数字」还是「仅中文」，据此决定替换哪些槽位 —— 英文字体不会把中文换成方块。
可变字体（Variable Font）友好：导入 VF 字体后，系统调节字重时依然可以平滑过渡。

2.7 谷歌字体兼容：解决 Chrome / Gmail 英数被换回去

现象：Chrome、Gmail 等谷歌应用的英文数字，会在 GMS 的 FontsProvider 下载 Google Sans 之后变回默认。

模块内置的开关，原理完全公开、且可逆：

- 做法：只停用 GMS 的 com.google.android.gms.fonts.provider.FontsProvider 组件，不卸载、不清数据、不动账户；随后强制结束 GMS 与谷歌商店进程，让已缓存的下载字体失效；
- 立即生效，不需要重启；
- 可逆：随时点「关闭兼容」；只恢复本模块自己停用过的组件（记录在字体库的 .gms_owned 里），如果你本来就手动停用过它，模块不会越权改动；
- 卸载模块时自动恢复。

（图3：谷歌字体兼容）

2.8 GitHub 在线更新

- WebUI 内「检查更新 / 更新日志 / 下载并安装」，不用再翻帖子找新版；
- 先校验再安装：校验 sha256（发布时由 GitHub Actions 自动写入）+ 校验包内模块 ID，任何一项不符都不会安装；
- 更新 / 覆盖安装不会清空字体库与设置，重启后自动恢复你上次选的字体；
- Magisk / KernelSU / APatch 的模块列表里也会提示「有更新」；
- 版本变过之后 WebUI 会自动作废旧缓存并重新检查。

四、安装与使用

4.1 刷前准备（必看）

- 先停用其他字体模块：多个字体模块会互相覆盖，包括你之前装的旧字体模块；
- KSU / APatch 用户建议关闭管理器的【默认卸载模块】，避免被隔离的应用看到的是系统默认字体（图5）；
- Magisk 没有 WebUI 入口，需要先安装 KsuWebUI（包名 io.github.a13e300.ksuwebui）或 WebUI X。

4.2 KernelSU / SukiSU / APatch 刷入

- Step 1：管理器 ➔ 模块 ➔ 从存储安装 ➔ 选中 custom-font-switcher.zip
- Step 2：刷入完成 ➔ 重启
- Step 3：重启后回到模块列表 ➔ 点模块卡片的 WebUI 按钮
- Step 4：导入字体 ➔ 点选字体卡片 ➔ 点「立即重启生效」

4.3 Magisk 刷入

- Step 1：Magisk ➔ 模块 ➔ 从本地安装 ➔ 选中 custom-font-switcher.zip
- Step 2：刷入完成 ➔ 重启
- Step 3：安装 KsuWebUI
- Step 4：回到 Magisk 模块列表 ➔ 点模块卡片上的「操作」按钮 ➔ 打开管理界面
- Step 5：导入字体 ➔ 点选字体卡片 ➔ 点「立即重启生效」

（图6：Magisk 的「操作」按钮）

4.4 导入字体

- 推荐「选择字体文件（可多选）」：在内置文件浏览器里勾选一个或多个 .ttf / .otf，直接复制入库，几十 MB 也是秒导；
- 备用「改用系统选择器」：大字体会明显慢一些；
- 导入后点卡片上的 ✎，可以修改名字。

4.5 从「自定义字体切换」旧版升级

直接刷入 v1.0 覆盖即可：版本号看起来变小了，但内部版本码更大，管理器会正常按升级处理；字体库保留，上次选的字体自动恢复。以后的新版本可以直接在 WebUI 里一键更新。

五、WebUI 状态说明与高级设置

因为系统字体在启动时就已加载，切换字体不会立刻改变，需要重启。页面上有两个状态：

- 当前实际生效：此时此刻系统正在使用的字体；
- 待生效（下次重启后）：你刚点选、已经生成好的新字体；
- 已替换槽位 / 实际挂载：本次替换了多少个槽位、开机时成功挂载了多少个。

生效方式：点页面底部「立即重启生效」，或自行重启。

高级设置（默认即可）：

- 保留日韩及其他文字的字体槽（推荐开启）：关闭后这些槽位也会换成你的字体，字体没有对应字符时会显示方块；
- 保留衬线 / 等宽 / 时钟 / 展示 / 斜体槽（推荐开启）：避免终端、锁屏时钟、斜体被统一成一个字形；
- 模块自带挂载（推荐开启）：特殊环境挂不上时，可一键切回「交给管理器挂载」。

改动设置后会按当前选择自动重新生成，重启生效。WebUI 支持深浅色跟随系统、手动切换主题与过渡动画。

六、常见问题与排查

6.1 小米 / 澎湃用户：部分界面没变（刷完做一次）

现象：设置界面变了，桌面或某些系统应用没变。

原因：系统当前使用的主题字体仍是默认的 MiSans 时，部分系统资源会被原厂字体覆盖。

解决：设置 ➔ 系统个性化 ➔ 字体 ➔ 手动切换为【小米兰亭Pro】。切换后系统会全量重新加载字体，即可全局生效。

ColorOS / OriginOS / Flyme / 原生一般不需要这一步，刷入重启即可。

（图7：切换小米兰亭Pro）

6.2 通用排查顺序

1. 打开 WebUI，看「实际挂载」是否成功、数字是否接近「已替换槽位」；
2. 点「查看诊断报告」，看「实际生效检测」的比例；
3. 若提示「本次开机没有执行自带挂载」，到「替换范围（高级）」关闭「模块自带挂载」，重新选一次字体后重启；
4. 仍然不行：在诊断报告里点「保存到 Download」，把报告 + 机型 + 系统版本发到评论区或 GitHub Issues。

6.3 高频问题

- 刷了完全没变化？→ 先看诊断报告里槽位是不是 0；小米用户先做 6.1；
- Chrome / Gmail 又变回默认？→ 打开「谷歌字体兼容」；
- 谷歌商店字体没变？→ 见第七节，属正常现象；
- 能不能内置字体？→ 不带字体：一是版权，二是把选择权留给你；
- 字体去哪里找？→ 开源字体项目（思源、霞鹜文楷、MiSans、HarmonyOS Sans 等），注意各自的授权条款；
- 检查更新失败？→ 国内访问 GitHub 不稳定，换网络或稍后再试，也可直接到 Releases 页手动下载刷入；
- 卡开机了？→ 再重启一次会自动恢复「无字体」；仍不行就进安全模式或在管理器里禁用模块。

七、已知局限（如实说明）

- 谷歌商店（Play Store）：新版把 Google Sans 直接打包进了 APK，属于「应用内置字体」，任何系统级字体模块都无法替换 —— Chrome / Gmail 生效、商店不变是正常现象；
- QQ、微信等个别页面走独立渲染或自带字体，不会随系统改变；
- 游戏、阅读器、网页指定的字体、图片里的文字，不经过系统字体，不受影响；
- TTC 合集不能直接导入，可用刷机包 tools 里的 optimize_font.py 拆出单个字体（电脑或手机 Termux 均可运行，也支持精简体积、可变字体转静态）；
- 部分厂商 ROM 的非标准字体槽需要反馈补充，我会按诊断报告加进内置清单。

八、安全、隐私与卸载

- 权限与网络：只做挂载和字体文件管理；除「检查更新」外不联网，不收集、不上报任何信息；
- 系统分区：只读挂载，绝不写入；
- 字体配置：不修改 fonts.xml 等配置文件；
- 卸载：在管理器中禁用模块即停止全部替换；点「卸载」会恢复本模块停用过的谷歌组件，并删除字体库 /data/adb/custom_font_lib。覆盖安装 / 更新不会删除字体库，你的选择和字体都在。

## 评论区常见问题（可置顶）

- 刷了没变化？→ 先看 WebUI「实际挂载」，小米用户切一次小米兰亭Pro，还不行发诊断报告。
- 会不会卡开机 / 变砖？→ 有开机保护，卡住的下次开机会自动恢复「无字体」；模块不写系统分区，禁用即还原。
- 能不能内置字体？→ 为了避免版权问题，模块不带字体，请自行导入。
- 字体从哪找？→ 各大字体官网、开源字体项目（如思源、霞鹜文楷、MiSans、HarmonyOS Sans 等，注意各自的授权条款）。
- 需要装元模块吗？→ 不需要，模块自带挂载，KSU / APatch 直接刷。
- 检查更新失败？→ 国内网络连 GitHub 不稳定，换个网络或稍后再试，也可以直接到发布页手动下载刷入。
- KSU 里部分应用还是默认字体？→ 到管理器设置里关闭【默认卸载模块】再重启。
