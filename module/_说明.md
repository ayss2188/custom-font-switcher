## 文件清单（27 个）

### 引擘（两个项目共用，改动要同步到子项目）

| 文件 | 作用 |
|---|---|
`common.sh` | 公共函数库：ROM 识别、设置读写、Root 管理器识别。**顶部有"重放清单"** |
`slots.sh` | **槽位发现** —— 决定"换哪些字体文件"，最核心的一块（53 KB） |
`mount.sh` | 自带挂载：`post-fs-data` 阶段把字体 bind mount 到槽位上 |
`post-fs-data.sh` | 开机的阻塞阶段：开机保护判断 + 触发挂载 |
`post-mount.sh` | 二次修补：别的模块的目录级挂载盖住我们时，靠 inode 比对补回来 |
`service.sh` | 开机完成后：撤保护标记、补完整计划、谷歌字体兼容补做 |
`ttcwrap.sh` | `.ttc` 合集处理（三星/魅族的中文在合集里，要包成同 face 数的合集） |
`nameclone.sh` | 字体名克隆：让系统认为字体名字没变 |

## ⚠️ 改之前必须知道

**① 引擘文件是"两个项目共享"的**
`common.sh` / `slots.sh` / `mount.sh` / `diag.sh` / `post-fs-data.sh` / `service.sh` /
`ttcwrap.sh` / `nameclone.sh` / `fontctl.sh` / `update.sh` —— 子项目（`D:\ds_porsche`）
用的是同一套。**改这些要在两个仓库都落地。**

**② 校验工具不能依赖加载顺序**
被别的脚本调用的工具函数，那个脚本得自己保证它可用 —— 否则会**静默跳过、等于没写**。
（这个坑踩过两次：`builtin.sh` 调 `fontctl.sh` 的 `valid_font`、`mount.sh` 调 `fontcheck.sh`）

**③ 别写死模块 id 以外的项目**
主项目 id 是 `custom_font_switcher`，子项目是 `porsche_font_*`。
`diag.sh` / `fontctl.sh` / `slots.sh` 里都有 id 兜底逻辑，改的时候别把兜底删了。
