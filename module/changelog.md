# 更新日志

## v1.2.0

### 一、修复：**字体"刷了不生效、切回无字体、一直转圈"**（重要，建议更新）

#### 现象

有用户反馈：刷上字体后**中文全变方块 → 自己切回无字体 → 再选也一直转圈**。
看起来像"模块把系统搞坏了"，实际不是。

#### 真相：字体库里留了一个 **16 字节的坏文件**

报告显示，字体库里除了真正该用的合集（几十 MB），还多了一个**只有 16 字节**的同名文件。
而挂载日志**每次开机都在重复同一句话**：

```
跳过无效字体（不挂到系统槽上）: …ttc5_2-3 -> /system/fonts/NotoSansCJK-Regular.ttc
跳过无效字体（不挂到系统槽上）: …ttc5_2-3 -> /system/fonts/NotoSerifCJK-Regular.ttc
```

**16 字节里当然没有字体** —— 但这个 bug 的根子不在"文件坏了"，
而在**模块没认出它坏了**：

```
判断"一个 .ttc 有几个 face"时，只查开头 4 个字节是不是 "ttcf"
→ 16 字节的垃圾头部正好也是 "ttcf"，于是它自称"我有 5 个 face"
→ 模块认为这个文件**结构完全正确** → 一直留着它 → 每次开机拿去挂载 → 每次失败
```

**修了两处，都是"与实现无关的硬底线"：**

| 修复 | 效果 |
|---|---|
合集判定加 **100 字节下限** | 16 字节垃圾 → 报 **0 个 face**（以前报 5）。一个 TTC 的头就有 `12+4×face数` 字节、每个 face 表目录至少 28 字节，**真合集不可能小于 100 字节** |
合集产物加 **1KB 兜底** | 产物不到 1KB 就是坏的 → **直接删掉**，下次重新合成，而不是一直带着这个坏文件跑 |

#### 顺手确认了一件事

用报告里那份字体逐字节复现，实测合成**本身是好的** ——
产物 47,336,064 字节、魔数 `ttcf`、5 个 face 名字全对。
**不是合成坏了，是判定太松。**

### 三、修复：**坏字体现在会被拦下，不会再挂到系统上**

有用户反馈「桌面、设置全是方块，有的 App 正常」。报告里查到根因：

```
他导入的字体内部只有：cmap loca head maxp post DSIG
  缺 glyf / CFF / CFF2  ——  也就是**没有任何字形轮廓**
```

**它自称有几万个字形，但存字形的表根本不存在** → 系统取不到字形，只能画空格子。
（就像字典目录写着「永在第 8000 页」，翻开第 8000 页是空的。）

**这个字体是旧版本模块导入的** —— 那时还没有这道检查，所以一路挂到了系统上。

#### 现在有两道关

| | 什么时候拦 | 拦什么 |
|---|---|---|
**第一道** | **导入时** | 魔数不对、文件截断、缺必需的表、**没有字形轮廓** —— 直接拒收，根本进不了字体库 |
**第二道**（这一版新增） | **应用前**（每次切换 / 重新生成） | 再验一遍**有没有字形轮廓** |

**为什么第二道必须有**：字体库里可能已经躺着旧版本导入的坏字体。
第二道在真正挂载之前再验一次，**遇到就拒收并说明原因**：

```
ERROR:这份字体里没有任何字形轮廓（缺 glyf/CFF）
      —— 挂上去会让中文全变成方框。请删掉它重新导入一份正常的字体
```

**所以以后遇到不能用的字体，不用重启一次才发现** —— 它会当场告诉你原因，换一份就行。

**校验发生在导入那一刻，而且看得见**：导入字体时进度条会显示
「正在校验字体文件：xxx.ttf」，不合格的**当场退回**、不会进字体库。
校验通过的结果会**记下来** —— 以后切换字体不用再把它读一遍。

#### 过程中修掉了这个检查自己的一个 bug

第一版是这么写的：把文件头部"洗成词表"，再精确匹配 `glyf` 这个词。
**但表目录里 tag 后面紧跟的是二进制校验和 —— 字母数字的字节会和 tag 粘成一个词**：

```
本该匹配到：glyf
实际洗出来：glyfY      ← 于是永远匹配不上
后果：      有 glyf 的**好字体被判成空壳**
```

改成**按 16 字节一条读表目录**（这才是字体的真实结构）。实测：

```
真机字体样本（25 张表）  -> 有轮廓  ✓
真机同款字体（21 张表）  -> 有轮廓  ✓
无轮廓的测试字体        -> 空壳    ✓ 正确拦下
```

### 四、新增：**「保留锁屏时钟字体」开关**（小米/红米/POCO 机型）

小米系的**锁屏时钟有自己专用的一份字体**（`miclock-*` / `mitype-clock` / `MiClock.otf` 这类），
以前它们会跟着一起被换掉 —— 结果就是**你在系统里换锁屏时钟样式，样式变了但字形还是你那套字体**。

**这一版加了一个开关**（设置页 →「替换范围」里，默认**关**）：

| 开关 | 行为 |
|---|---|
**关**（默认） | 连锁屏时钟也换成你的字体 —— 和以前一样 |
**开** | 那几份锁屏字体**保留原样**，你还能在系统里挑锁屏时钟样式；**其余所有槽位照旧全替换** |

**判据是精确的**：按 **family 名里带 `clock`** 认，不是靠"是不是特殊字体"这种模糊猜测。
实测实机配置：**认出 34 个锁屏字体，全部正确、无一个误伤**。

> 其他厂商的机型**没有**锁屏专用字体族，这个开关开了也不影响任何东西。
>
> 顺便说明：以前也有一个"保留特殊槽"的大开关，它把等宽、斜体、衬线、装饰体**一锅端**地留下，
> 用户体感就是"替换不全"。那个已经去掉了 —— 现在只有这一个**精确**的开关。

### 五、优化：**切换字体更快了**（少做重复的活）

字体切换背后要做几件"扫描"的活，而它们的结果**平时根本不会变**
（配置没改、清单没改、字体没换），以前却每次都要重算一遍。这一版把它们**存起来了**：

| 存什么 | 存在哪 | 什么时候重算 |
|---|---|---|
**哪些字体是锁屏专用字体**（开了「保留锁屏时钟字体」才用到） | 缓存目录 | 系统字体配置变了 |
**这台设备有哪些"没人管"的字体**（自适应扫描的结果） | 缓存目录 | 配置 / 清单 / 字体目录变了 |

**存的是结果，不是猜测** —— 缓存和重新扫出来的**结果完全一致**（比对过），
只为省掉重复劳动；一旦上面任一条件变了会自动重扫，不会用旧结论。

> 顺带：导入字体时那次校验的结论也一起记下了，切换时不再重读字体文件。

### 六、修复与优化

- **报告的"每一步耗时"有两处是错的**：`PZ1 TTC头信息` 原来记的是它**前面**那段的耗时，
  TTC 段根本没被测到（真机那句"223 秒"就是错的，会把人带偏）。已拆成两条，各自记自己那一段。
- **报告生成更快**：原来"打包原始配置与哈希清单"这一步是**每个文件起 2 个进程**去读大小和修改时间
  —— 字体目录大的机器有 200~270 个文件、总共 1 GB 以上，也就是 **400~550 次进程创建**。
  现在改成"每个目录一次读完、之后查表"：实测查表结果与逐个读**完全一致**（含带空格的文件名）、
  报告正文**逐字节不变**、全量回归 **12 套件 0 失败**。
  （报告里最贵的两步（实测"自适应扫描 108 秒""候选枚举 38 秒"）这一步没动，下一步会针对它们。）
- **诊断报告界面**：去掉了重复的横幅文案；去掉了所有"可以关窗口 / 任务在后台继续"的提示
  —— Android 会把后台的 WebView 冻住甚至杀掉，"关掉"其实等于"取消"，说了反而误导人。
- **更新进度现在能看全了**（原来那一版几乎看不见过程）：
  - **以前**：点更新之后，进度条停在「准备中」，然后**一瞬间就跳到"已更新完，请重启"** ——
    中间下载了多少、装到哪一步了，完全看不到。字体包几十 MB、装机又要十几秒，
    这段时间界面像卡住一样，很容易让人以为死机了，然后手贱去关窗口。
  - **现在按顺序给你看**：
    ```
    正在连接 GitHub…  →  正在下载刷机包 12.3 MB / 45.7 MB（27%）
                      →  正在校验刷机包…  →  安装完成，重启后生效
    ```
    - **下载阶段** —— 按实际收到的字节数走，**已下载 / 总大小 / 百分比**都实时在变；
    - **安装阶段**（新增）—— 按安装器日志的**增长量**和**已用时间**双重估算，进度条会真的走，
      不再是一进去就 100%。
  - **卡住会提醒**：连续十几秒字节数完全没变，会提示"下载好像卡住了…还在重试，如果一直不动可以换网络再试"
    —— 只提醒、**不中断**，免得网络一抖动就把已经下好的部分丢掉。
  - **失败会说清楚是哪一步失败**（下载 / 校验 / 安装），不再静默跳完。
- **底部按钮**：修掉了窄屏上被挤没的问题（小屏 / 大字体设置下）。

### 一、修复：**"没适配过的机型"其实一直没被兜住**

这个模块有一个设计：**没主动适配过的机型，靠"读你自己的字体配置"自动兜住** ——
扫一遍你机器上的字体配置，减掉清单里已经有的，**剩下的就是没人管的，模块自己接管**。
所以就算某个机型我们没适配过，你也能用。

**但这条链路断了**（早前一次"提速"改坏的，改完看着像优化，实际把整段功能关掉了）：
它本该去"扫描设备配置"，结果改成拿"清单已经算出来的候选"来扫 ——
**从已经有的里面挑，当然挑不出新的**。于是自适应等于关闭，而且**只有没适配过的机型会踩到**，
报告里也看不出来（报告会说"模板已覆盖本机需要的角色"）。

顺便修掉同一条链上的第二个 bug：扫描结果里 **`lang="und-Nkoo"`（西非 NKo 文字）**
因为语言码里含 "ko" 被当成**韩文**、`lang="und-Java"`（爪哇文）含 "ja" 被当成**日文** ——
真补进去的话，**这两种文字会被换成你的字体、变成方块**。

实测（模拟一台"完全没适配过"的机器）：

```
修前：计划 = main + cjk                      ← 韩文/日文永远不换
修后：计划 = main + cjk + hangul + kana       ← 补对了
      NKo / 爪哇文 没有被误换                  ← 也没换错
```

> 如果你用的机型已经在清单里，这条你**没有直接感知**。它的意义是：
> **以后遇到没适配过的机型，模块能自己兜住，不用等我加清单。**

### 二、修复：诊断报告两个视图的框大小不一样

有用户反馈"切到原样文本，框缩成中间一小块、什么都看不到"。实测（量真实高度）：

| 内容 | 修前：结构化 / 原样 | 修后 |
|---|---|---|
0 节 | 90 / 90 | **349 / 349** |
1 节 | 104 / **90** | **349 / 349** |
1 节+未完成 | 186 / **90** | **349 / 349** |
12 节 | 339 / **90** | **349 / 349** |

原因：两个视图在弹窗布局里被压到 90px 下限（**原样文本永远只有 90px**），
而结构化视图跟着内容变 → 两个框大小不一致。
现在两者用同一套规则、都填满可用空间、都不许被压扁。

### 三、新增：三星 One UI 专属字体清单

以前 `targets/` 里只有 5 份清单（澎湃 / ColorOS / OriginOS / Flyme / AOSP）—— **三星一直没有**，
只能靠"读你自己的字体配置 + 自适应扫描"撑着。

某个角色已经有候选了，**个别漏网的字它就不会补**。三星真机上实测漏了 3 个：

（如果你用的是三星：重启一次后，韩文和这两个装饰字也会跟着你的字体变了。）

### 四、新增：魅族 19 个自有字体

魅族真机报告里发现 **12 个魅族自有字体在清单里一份都没有**
（`SFDIN-*` / `SFPRO-*` / `DMSerifDisplay` / `FlymeNumber-VF`），

### 五、修复：`SFPRO-SemiCondensed*` 被判成"符号" → 永远不替换

角色判定里的符号规则用 `*icon*` 做匹配，而它**命中了 "sem·icon·densed"** ——
于是 `SFPRO-SemiCondensedBold/Light.otf` 被判成"符号字体"，而符号是**永不替换**的。

真机证据：2 份魅族报告里这两个文件都在、都被配置引用，**却一个槽位都没进计划**；
而且报告也不会点名它（报告按角色分类，`sym` 算"正常排除"）。

已修。**真符号（emoji / 各种 Symbol 字体）行为不变。**

### 六、修复：模块内的更新日志被截断

`update.sh` 读更新日志时限制了长度，上限原本写成了 30000，
而日志文件已经 **44,849 字节** —— 实测**后 5 个版本（v1.0.4 及更早）整段看不到**。
已恢复成 60000。**你现在点「更新日志」应该能看到全部历史版本。**

### 七、修复：升级后字体没了 / 回到默认

两个"不报错但结果不对"的问题：

- **恢复上次选择的解析链**：跳过空值和 `none`、优先读"当前真正生效"的那个。
  以前 `pending_font` 里写着 `none` 会挡住后面所有来源 → 升级完字体没了。
- **兜底结果不再被覆盖**：兜底挑好字体后，紧接着一句无条件的"清成无字体"又把它盖掉
  → 用户重启回到默认、必须重新选一次。

### 顺带说一句

这一版还修了一批**字体文件本身的元数据缺陷**（`head.flags` 等三个字段写错）——
那种缺陷会导致**个别加固 App 无栈静默闪退**，而模块自己的所有测试都查不出来
（因为它不在代码里，在字体文件的字节里）。模块新增了 `check-font-meta.py`，

如果你装完发现某个应用还是闪退，麻烦把诊断报告发我 —— 报告里能看出字体挂载的实际状态。

| 第 1 步（结论与门禁） | **1371 秒** | **49 秒** |
| 合计 | **1838 秒** | **329 秒** |

**报告内容一行没少** —— 提速全部来自"同样的结果、更省的做法"：

- **第 0 节不再"每个字体起好几个进程"**：原来逐个字体调用判定函数，每个里又套子进程
  → 500 多个进程，光这一节就 253 秒。现在整节**零子进程**完成 → 1 秒。
- **不再把自己降到最低优先级**：v1.0.9 起把 CPU 降到 nice 19、磁盘降到"空闲类"
  （含义是"只要有别人用磁盘就让路"）。而报告要起**几千个短命进程**，
  手机持续有后台读写时等于每个都排在队尾 —— 同一个采集单独跑 32 秒、在流程里要 6 分多钟。
  现在只做有节制的让路（nice 10）。
- **不再每阶段整份复制报告**（原来 7 个阶段复制 7 遍，最后只写 1 次）。
- **去掉两处"每 25 个文件睡 1 秒"**的白等（几十秒）。
- **逐文件指纹改成稀疏指纹**（大小 + 修改时间 + 头尾各 64KB）：读盘量降到约 1/20，
  **尾部改动照样能发现**（报告开头的口径说明已如实改成"稀疏指纹"）。
- **修掉三处"同一件重活干好几遍"**：字体目录列表、第 0 节的查表、替换计划的候选枚举。

> 说明：我还试过"第 6 步把 293 次 `stat` 合并成每目录 2 次"，**真机实测反而更慢**
> （288 → 314 秒：纯 shell 的大字符串查表比直接起一次 `stat` 还贵）。**已经撤回。**

### 新增：点「查看诊断报告」时当场选快慢

### 报告新增两节（用来定位"没生效 / 没适配"）

- **【4】★ 语言 → 字体文件**：这台系统"靠什么生效"，一行一种语言：

- **【5】★ 没被替换的字体**：列出**真实存在、被配置引用、但本次计划里没有**的字体，
  分成两类 —— `[★要修]`（本该参与替换却没进计划）和 `[正常排除]`（其它文字体系/符号，
  换了反而出问题）。**看第一类就行。**

  这一节这轮改了三次判据，最后才是对的：

  1. 最初写成"在不在适配清单里" → 真机上输出"没有没适配的"，
     但同一份报告的【0】节明明列着漏网的 —— **清单里有 ≠ 会被替换**，

     现在改成**三级兜底**（内存表 → 直接问文件系统 → 才跳过），并**直接从字体目录列表**建表。
  3. 真机终于出数后，又抓到 2 个**误报**：`DelaGothicOne.otf` / `-HZ.otf` 被标成"要修"，

     模块**刻意不换**。**文件名里没有 clock 字样，所以只看文件名会漏。**

     `clock / watch / lockscreen / widget / emoji / symbol / logo / brand` 时算"正常排除"。

  **这一节现在还带诊断量**，下次出问题一眼能看出是哪一层空了：

## v1.0.6

本次三件事：**更新检查更可靠**（刚发布的版本能立刻检查到，不用等缓存）、**体检报告会判定"桌面变了但 App 里没变"**（Root 管理器"对应用卸载模块"造成的，附处理办法）、**谷歌字体兼容重做**（Google 系应用的英文数字不再"过一阵又变回谷歌默认"）。

**新增：报告会判定"App 里没变"的原因**

- 有些 Root 管理器默认会对应用"卸载模块"（KernelSU 系的「默认卸载模块」**默认就是开的**）。表现是：
  **桌面、状态栏、设置里的字都变了，但普通 App 里的字没变** —— 而挂载日志一切正常、报告也显示全部生效。
- 现在体检报告会**进到 App 自己的挂载命名空间里数一数**：如果确实是这个原因，会直接写出来，
  并告诉你怎么办（到管理器里关掉「默认卸载模块」，或只给那一个 App 关）。
- 顺带一条**正常现象**：网页 / 小程序 / 内置浏览器属于 WebView，它的渲染进程在这类管理器上
  一定会被"卸载模块"，所以这类内容里的字体本来就不受本模块影响。

**新增：谷歌字体兼容重做（默认关闭）**

- Google 系应用（Play 商店、Chrome 等）会通过 Play 服务下载字体（Google Sans / Product Sans 那类），
  这些字体**不经过系统字体目录** —— 以前的表现是"中文变了、英文数字过一阵子或重开商店又变回谷歌默认"。
- 这一版的改进：
  · **Play 服务更新后会自动补上**：以前它一更新就被顶回原状态，现在每次开机检查一次，被顶回去就自动重新生效；
  · **不再强杀 Play 服务**：以前每次开关都会强制停止 Google Play 服务和 Play 商店（会打断推送、后台同步），
    现在只清后台进程，并且有频率限制；
  · **支持多用户 / 工作资料**：以前只对第一个用户生效；
  · **状态显示更诚实**：读不到就说"读取失败（未知）"，不会再假装"未开启"；

## v1.0.5

本次更新四件事：**中文不再"换不掉"**（三星 / 魅族 / vivo 等机型）、**加粗终于有真的粗体**（同族多字重自动配对）、**开机保护更硬**（连续两次开机失败会自动停用本模块，保证手机能开机）、**导入前先体检字体并检查空间**（坏字体和写满 `/data` 都拒之门外）。
另外还有一个**行为调整**：不再替换「设置里选的字体」，详见下面第一条。

**改动：不再替换「设置里选的字体」（默认关闭，可手动打开）**

- MIUI / HyperOS、三星、vivo 都会把你「设置 → 字体样式」里选的字体放在单独目录
  （`/data/system/theme/fonts`、`/data/overlays/font`、`/data/vfonts`），**那里的优先级高于系统字体目录**。
- v1.0.4 会把它们一起替换掉，这带来一个真实问题：有用户选「**小米兰亭 Pro**」正是为了能调「**字体粗细**」——
  被换掉之后粗细直接调不动了（系统靠可变字体的字重轴实现，普通字体没有这个轴）。
- 本版**默认不再替换**这些目录：你在设置里选什么就是什么，粗细也照常能调；本模块只负责系统字体目录里的槽位。
- 想让它连这些目录一起接管（省得去设置里切回「默认」）：打开界面上的
  「**也替换『设置里选的字体』**」开关即可，代价是设置里选的那个字体失效。
- 顺手修了一个隐藏问题：这些目录里常常是"**一个真实文件 + 一堆符号链接**"（实测 18 个文件全指向同一个），
  以前会挨个去挂那些符号链接（不可靠，真机上"实际生效"校验会对不上）。现在**只替换那个真实文件**。

**新增：报告会说清"为什么调不了粗细"**

- 如果本机原本的字体是**可变字体**（带字重轴，如 `MiSansVF`、`MiuiEx-*`），而你导入的是单字重字体，
  报告结论区会直接写明：**替换后系统设置里的「字体粗细」调节会失效**（普通字体没有字重轴），
  并给出两条出路：① 导入可变字体；② 想让「加粗」变粗就把同族的 Bold 一起导入（本版的多字重配对）。

**新增：多字重配对 —— 加粗终于是真的粗体了**

- 以前的毛病：系统显示**加粗**时，是去同一族里找 **weight=700 那份文件**（`MiSans-Bold`、`SourceSansPro-Bold`…）。
  而本模块以前**一个字体铺满所有槽位** —— 系统要 700，拿到的还是 Regular，所以**看不出加粗**。
  主题包（MTZ）之所以能加粗，就是因为它是**成套**的：Regular / Bold / Light 各一份。
- 现在：**把你导入的同族多个字重自动配对**，不用手动设置 —— 系统要粗体就给 Bold、要细体就给 Light、
  要常规就给 Regular（判断依据是字体自带的族名，同一族的文件自动认成一组）。
- 用法：把同一个族的几份一起导入就行，例如
  `思源黑体-Regular` + `思源黑体-Bold` + `思源黑体-Light` → 界面会标上「**同族 3 个字重**」。
- **只导入一份时行为完全不变**（不做任何额外处理，不影响绝大多数用户）。
- 导入时还会直接告诉你结论：可变字体 → 「字体粗细」调节有效；只有单一字重又没有同族伙伴 →
  明确说明"加粗不会有变化，这是字体本身的限制"（不是模块坏了）。

**新增：开机保护 —— 连续失败会自动停用本模块**

- 有用户反馈：老设备换字体后**卡开机动画**，强制重启后黑屏、进不了桌面。本版加了三道保护：
- **① 连续两次开机没能完成 → 自动停用本模块**（写入禁用标记）。管理器下次开机就不会执行它，
  **手机保证能正常开机**。原因会写进模块描述里；重新启用后界面也会弹出说明，提醒你
  "**先换一个字体**再试"。（只在第二次才停用，偶发一次不会误伤。）
- **② 开机阶段只做必需的事**：需要合成几十 MB 的 `.ttc` 合集这类重活，一律**等开机完成之后**再做，
  绝不占用开机的阻塞阶段（老设备上这就是"卡开机动画"的来源）。当次不受影响，下次重启生效。
- **③ 超时是硬保证**：即使系统里没有可用的 `timeout` 命令，每一步也一定会到点结束 ——
  任何一步都不会把开机卡死。

**新增：中文不再"换不掉"（三星 / 魅族 / vivo 等机型）**

- 这些机型的中文来自 **`.ttc` 合集** —— 一个文件里装着日文、韩文、简体、繁体好几套字。以前的版本只能替换 `/system/fonts` 里的单文件字体，中文那份合集换不掉，于是表现成「**英文变了、中文没变**」，很多 App 看起来像没生效。
- 现在会把你的字体**包成同样 face 数的合集**顶上去顶替它，**只换中文那几号**，日文 / 韩文保留系统原本的字形 —— 所以不会出现日文韩文方块。
- 这类机型**自动打开**（判断依据来自你手机里的字体配置，不认机型名），也可以在「替换范围（高级）」里手动开关。
- 「保留繁体 / 日文 / 韩文」开关对它同样有效：**默认繁体保持系统字体**，想让繁体也一起换就关掉那个开关。
- **空间管理**：换字体后会清理不再使用的合集文件，不会越积越多；空间不足时跳过该槽位，而不是写满 `/data`。
- **保守的兜底**：万一读不到你这台机器的字体配置，就**只动最可靠的那一号**（2 号 —— 简体中文在 Noto / 三星这套合集里的位置）：
  宁可"只让中文跟着变"，也绝不去赌别的语言（猜错就会把日文换成你的字体、日文变方块）。
- 已实测：三星 SM-S9280 / Android 16 通过（**中文跟着变**）。
  说明：那次用的是"整份替换"的测试包，所以**"日文韩文保留"这一点当时还没有真机确认** ——
  这一版的实现进一步收窄成"只换中文那几号"，仍需一份真机报告来确认（见 v1.0.6 最后一条）。

**新增：导入前先做"字体体检"，坏文件直接拒收**

- 以前只检查文件开头 4 个字节 —— **被截断、下载了一半、损坏的字体同样能通过**。而把坏字体挂到
  系统字体槽上，轻则个别文字显示异常，重则开机后系统字体加载失败。
- 现在会验证整张表目录：表数量是否合理、每条表的**偏移+长度是否落在文件内**、必需的几张表
  （`cmap`/`head`/`hhea`/`hmtx`/`maxp` 与轮廓数据）是否齐全。截断文件、空壳文件都会被拒收，
  并明确提示"**可能已损坏或被截断**"。

**新增：导入和生成合集前先算空间，避免写满 `/data`**

- 字体动辄几十 MB，换成 `.ttc` 合集还要再翻一倍。**`/data` 写满会直接导致黑屏、进不了桌面**，
  而且很难想到是字体模块干的。
- 现在：导入前要求空间足够（字体大小 ×4 + 20MB 余量），不够就拒收并说明原因；
  合成每个合集前也会**单独算一次**，不够就跳过那一个槽位（其他槽位照常替换），
  并在诊断报告里写明"空间不足跳过"。

**修复：「实际挂载」谎报"本次开机未挂载"**

- 有些情况下（本次开机没有新的挂载动作、或计划里的槽位都已被跳过），**字体明明生效了，界面却说"本次开机未挂载"**，让人以为更新失败。
- 现在按真实记录显示：`成功 18`、`本次开机未改动（已就位 6）`、`跳过 31`；**只有真的失败才标黄**（以前连"失败 2"都会被吞掉、显示成未挂载）。

**修复：`实际生效 N/M` 里的 M 不再虚高**

- 换过 ROM、或系统更新删掉了某些字体文件之后，计划里会留下**设备上根本不存在的槽位**，界面就会出现「实际生效 24 / 62」这种看着像"只成功了一半"的数字。
- 现在不存在的槽位**不计入总数**。

**修复：某些管理器上"一个槽位都没换"**

- KernelSU / APatch 以前把开机挂载完全让给 `post-mount` 阶段，而**有些管理器根本不执行那个阶段** → 字体一个槽位都没换，用户只会看到"本次开机未挂载"。
- 现在 `post-fs-data`（所有管理器都一定会执行）就是主挂载点；`post-mount` 保留做"二次修补"（幂等，不会叠挂载）。

**修复：挂载计划丢失时静默不挂**

- 极少数情况下（更新安装后计划没落盘），重启后一个槽位都挂不上、日志里什么都没有，报告只能写"未挂载"，用户无从下手。
- 现在挂载前会**自己把计划补一次**：开机阶段先把普通字体挂上（当次生效），需要合成合集的完整步骤在**开机完成之后**补做。

**诊断报告：多了两段"现场结论"，出问题一眼看得出**

- 「**合集替换决策**」：这次换了哪几号 face、是**按你手机的字体配置判的**还是按惯例兜底的。
- 「**合集 face 名单**」：原合集与我们生成的合集，每号 face 的名字并排显示。
- 导入字体后直接告诉你它覆盖了哪些文字：
  `英文 ✓ 数字 ✓ 简体 ✓ 繁体 ✗ 日文 ✗ 韩文 ✗` —— 并说明**缺的部分会自动保留系统字体，不会出现方块**。
- 同时告诉你**这个字体能不能被系统加粗 / 调粗细**：
  - 同族有多个字重（已配对）→ 提示"加粗/细体会各就各位"；
  - 可变字体 → 「系统的『字体粗细』调节对它有效」；
  - 静态单字重又没有同族伙伴 → 「只有一个字重（wght=400）：系统的加粗 / 粗细调节不会有变化」，
    并说明这是**字体本身的限制**（想加粗就把同族的 Bold 一起导入，见上面「多字重配对」）。
  - 字体列表里也会标出来：可变字体标「可变」，静态字体标「字重 400」，配对成功的标「同族 N 个字重」。

**修复：报告里两处数字算错了**

- `.ttc 合集`的 face 数显示成 `83886080`（其实是 5）—— 字节序读反了。
- 「上层挂载点数量」严重低估：有用户 24 个槽位全部挂上了，报告却只显示 6 —— 它以前只数 `/system/fonts`，漏掉了 `/product/fonts` 这些厂商目录。

**更新通道：更新弹窗里的说明不再依赖 raw.githubusercontent.com**

- 管理器更新弹窗读的**更新说明**以前从 `raw.githubusercontent.com` 取，国内经常连不上、显示 **Not Found**。现在改走 jsDelivr CDN，并且只放**本版的简短说明**（完整日志在模块内「更新日志」和 GitHub Release 页）。

**其他**

- 开机后会清掉指向"已不存在的字体文件"的失效记录（界面上"已替换槽位"的数字不再虚高）。
- 已知局限更新：**「`.ttc` 合集不替换」这条本版已不再成立**；新增「**输入法 / 键盘**通常自带字体，不受本模块影响」。

## v1.0.4

**修复：繁体中文出现方块**

- MIUI / HyperOS 的繁体（`zh-Hant`）由单独一份字体（如 `MiSansTCVF.ttf`）接管，以前的版本会把它一起替换掉。如果你导入的字库没收冷门繁体字（如「靉」「鶚」「懞」），那些字就会显示成方块。

- 选完字体但还没重启时，报告会报"❌ 挂载阶段没有留下任何记录 / 需要改用其它挂载时机" —— 现在明确告诉你「**字体已经选好了，重启一次就生效**」。
- 「简中指向 .ttc」以前直接断言"中文不会被替换"，说得太绝对：那只是**兜底字体**，主字体家族被替换且自带中文字形时中文一样会变。现在按实际情况分开说明。

**修复：「实际挂载 成功 18」看着像丢了 6 个槽位**

- 有 6 个槽位是**同一份文件的两条路径**（如 `/system/fonts/X` 与 `/product/fonts/X`），挂上一条另一条自然就生效，不再重复挂 —— 以前只显示"成功 18"，容易被当成丢了 6 个。
- 现在写成「成功 18，另 6 个已生效（无需重复挂）」，并新增一行「**实际生效（逐个核对）**」：按 inode 逐个核对每个槽位，一眼看出有没有真的生效（如 `26 / 26 个槽位`）。
- 报告第 2 节的 `mount.state` 也补上了 `same=` 并附上怎么读。


**界面说明改清楚了**

- 两个「保留」开关以前只写"推荐开启、否则会显示方块"，看不懂到底管什么。现在直接写明**开着是什么效果、想让这些也用你的字体就关掉它、以及风险**：
  - 「保留繁体 / 日文 / 韩文字体槽」—— 补上了**繁体**（以前只写"日韩及其他文字"，没人知道它管不管繁体）
  - 「保留衬线 / 等宽 / 时钟 / 斜体等特殊槽」—— 去掉了看不懂的"展示"，改成说清终端、锁屏时钟、衬线、斜体
- 顶部「实际挂载」那行以前太长会换行（"自带挂载 成功 17，另 9 个已生效（无需重复挂）"），现在缩成 `成功 17，已就位 9`，有没有真的生效交给下一行「实际生效（逐个核对）」。

- **点「查看诊断报告」要等一会儿才出东西**：以前脚本每次启动都会先做一次真的「挂载实测」（真挂一个槽位验证再卸掉），所以打开报告、读取状态这些动作都得先等着它。现在只有真正生成报告时才做实测，其余时候界面直接读状态文件，点了立刻就有反应。
- **报告最多只等 2 分钟**：以前超过 2 分钟就提示"任务可能还在后台"，之后不再理你。现在界面最多等 60 分钟，脚本自身 45 分钟到点会**保存已完成的部分**再收工。
- **弹窗里没有「中止生成」**：以前只能点「关闭」，任务还在后台继续跑、也不知道停没停。现在有「中止生成」（点了立刻停，已完成的部分照样保留）和「重新生成」。
- **生成报告时不再把整机拖卡**：以前生成过程不做任何让路，字体多的机器上会明显发卡。现在全程把 CPU 和磁盘优先级降到最低，并且定期让出资源。

**开机 / 关机相关修复**

- **修复「换了字体开不了机」**：以前的开机保护标记会在等待超时后被无条件删掉，导致自动救援永远等不到机会——同一个坏字体每次开机都会再挂一次。现在**只有真的开机完成才会清标记**。
- **修复「字体选择莫名被清空」**：现在保护标记里会记下本次开机的 ID，配合开机心跳日志判断上次到底有没有开机成功，避免"其实成功了"却被当成失败而清掉你的字体。
- **救援更可靠**：以前救援依赖一个可能缺失或损坏的配置文件，一旦缺失就会跳过删除、还会顺手清空待清理清单，导致**再也救不回来**；现在两种落盘方式都会删，删完才清清单。
- **关机更顺**：模块的等待流程（开机服务、卸载、更新下载、报告生成）现在都会感知"正在关机 / 重启"并立刻收工，不再拖着关机流程。
- **卸载更安全**：卸载时的后台任务不会在"你又把模块装回来了"或"正在关机"的时候把字体库删掉。
- **挂载更稳**：每个槽位的挂载加了 5 秒超时（一个卡住的挂载不会再拖死整个开机阶段）；已经指向本模块文件的槽位会直接跳过，不会重复叠挂载层；`post-mount` 只在 KernelSU / APatch 下执行，避免和 `post-fs-data` 各挂一遍。

**更快**

- **不再把同一份字体反复计算**：厂商 ROM 里常有多个路径指向同一个字体目录，以前会把同一批文件哈希好几遍（这是"最后一步特别慢"的主要原因），现在按 `设备号:inode` 去重，只算一次。
- **不再"每个文件起一个进程"**：改成一个目录一次 `stat`、一批 20 个文件一次 `sha256sum`、魔数一次读完整个目录、表信息从 5 个进程降到 2 个。以前几百个字体就是几千次进程创建，CPU 会被瞬间打满。
- **继续对闪存友好**：快速体检只读每个字体的**前 1 MB** 算"头哈希"（报告里标记为 `h:`），并在选口径时写明**读盘量**（如"快速体检约 40 MB；完整报告要全量读约 620 MB"）。
- 下载新版的超时从 300 秒收紧到 180 秒，不再让下载任务长时间挂着。

**文件名与操作变化（习惯一下）**

- **生成完自动保存**，原来的「保存到 Download」按钮已经去掉（它和自动保存重复）。
- 报告文件名按口径分开，互不覆盖：
  - 快速体检 → `Download/快速体检报告.txt`
  - 完整报告 → `Download/完整体检报告.txt`
  - 生成中途 → `Download/未完成的体检报告.txt`
  - 另留一份固定名 `Download/font_diag.txt`（内容 = 最近生成的那一份）
  - 万一 Download 写不进去（存储满等），会自动退回固定名、再退回模块目录，并在界面上显示**实际存到了哪里**。
- 点「查看诊断报告」后**先在界面里选「快速体检 / 完整报告」**，不再弹第二次确认框。

## v1.0.2

**新增：诊断报告（一键体检）**

- 在 WebUI 里点「查看诊断报告」或「保存到 Download」，或点模块卡片上的「操作」按钮即可生成；报告在后台生成，界面不会卡，窗口可以随时关掉。
- **结论优先**：报告第一段直接给出「为什么没生效」的判断——模块是否被禁用 / 待卸载 / 尚未激活、是否处于安全模式、是否与 Magisk 共存、本次开机的 post-fs-data 与 service 有没有被执行、挂载能不能成功；后面再跟 10 节明细。
- **实机挂载实测**：现场取一个真实槽位做 bind 挂载 → 校验 设备号:inode → 立刻卸载还原；能不能挂当场有结论，失败会带出真实报错。
- **实际生效的字体目录（第 5 节）**：列出本机每个字体目录的真实路径与 `dev:ino`（识别符号链接、判断两个目录是不是同一份，同一份只需替换一次）、配置里每个字体名按 Android 规则解析后**框架真正会读的那个路径**、以及同名文件在别的目录里的**独立副本**（只替换一份时个别应用可能仍读到旧字体），最后给出替换计划分别落在哪些目录。新机型要精准适配，靠的就是这一节。
- **MIUI / HyperOS 个性字体检测**：检查 `/data/system/theme/fonts` 等主题字体目录，列出里面的字体以及与系统字体**同名**的那些（它们会被个性字体顶替，只替换 `/system/fonts` 不会全面生效），并给出「设置 → 显示 → 字体大小和样式 切回默认后重启」的处理建议。
- 其余覆盖：槽位候选与替换计划（含被「保留」的槽位）、设备上全部字体目录清单、系统字体配置（fonts.xml / fonts_additional / font_fallback / fonts_customization 以及分区与 apex 下的）中 sans-serif 族与中文族的原文、配置引用的文件是否存在、所有 `.ttc` 合集及其 face 个数、字体包（flipfont）、`/data/fonts` 可更新字体、主题 overlay 等可能接管字体的来源，以及 KernelSU 日志与内核信息。
- 报告保存为 `Download/字体体检报告.txt`（另有一份内容相同的 `font_diag.txt` 备用名）；点「保存到 Download」写出的版本还会带上原始字体配置、每个字体文件的 sha256 与 sfnt 表信息、实际字体目录映射。反馈问题时发这一个文件就够。
- 新增**开机心跳与挂载日志**：每次开机 `post-fs-data` / `service` 是否执行、挂载成功多少失败多少、失败的真实报错都会记录，并直接体现在报告里。

**WebUI**

- 每次打开 WebUI 都会自动检查一次更新（以前是每天最多一次）。
- 下载新版时显示**进度条**：实时显示「已下载 / 总大小（百分比）」，之后依次显示「正在校验」「正在安装（管理器解包中）」「安装完成」。

## v1.0

首个正式版本。

**字体**

- 默认不替换任何字体，导入自己的 TTF / OTF 字体（可多选）一键切换，选「无字体」即恢复系统默认。
- 导入时自动识别字体覆盖范围（中英文 / 仅英文 / 仅中文），英文字体不会把中文换成方块。
- 字体库和设置存放在 /data/adb/custom_font_lib，更新模块不会丢，更新后自动恢复上次的字体选择；卸载模块时字体库和设置一并删除，不留残留。
- 配套字体精简工具 optimize_font.py（电脑或手机 Termux 均可运行）：精简字体体积、可变字体转静态、从 TTC 合集中取出单个字体。

**适配**

- 按本机真实字体目录和字体配置 XML 发现槽位，只替换手机上真实存在的字体文件；默认保留日韩及其他文字、符号、衬线、等宽、时钟、斜体等槽位。
- 支持 HyperOS、ColorOS、OriginOS、Flyme、三星、荣耀、华为、Nothing 和原生系统，自动发现未知厂商字体分区。
- 模块自带挂载：KernelSU / APatch 不需要元模块，能覆盖 my_product、mi_ext 等厂商分区；也可切换为交给管理器挂载。

**安全**

- 切换字体「先生成、再校验、最后提交」，中途失败保留原来的字体。
- 开机保护：选字体后没能开机，下次开机自动恢复为「无字体」。
- 检测其他字体模块并提示，避免互相覆盖。

**其他**

- 谷歌字体兼容开关：解决 Chrome / Gmail 等英文数字被 GMS 下载字体覆盖；只恢复本模块停用过的组件，卸载时自动恢复。
- GitHub 在线更新：WebUI 内检查更新、查看更新日志、一键下载安装（自动校验 sha256 和模块 ID）；管理器模块列表也会提示更新。
- 模块卡片「操作」按钮：Magisk 下用 KsuWebUI 打开界面，并显示状态、检查更新。
- 诊断报告：设备信息、槽位统计、挂载结果、实际生效检测、冲突模块等，可保存到 Download。
- WebUI 支持深浅色跟随系统、主题切换与过渡动画。
