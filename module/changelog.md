```

## v1.5.1.3

### 一、修「WebView / 米家这类界面字体没换」

```
· HyperOS 上 /system/fonts/MiSansVF_Overlay.ttf 是指向
  /data/system/fonts/theme_webview/Roboto-Regular.ttf 的符号链接
· 以前所有 /data 槽位一律跳过（不写用户盘），这个目标文件就从来没被换过
  → WebView 渲染的页面（米家控制页这类 H5）读到的还是原来的字体
· 现在对 /data/system/fonts/theme_webview 和 /data/system/theme/fonts 两类目录
  做 bind 挂载（只挂载、不写盘，不动其它 /data 槽位）
```

### 二、自检不再把「策略性跳过」算成「看不到」

```
· PID 1 视角校验里，按策略跳过的 /data 槽位单独排除，不再误报
```

## v1.5.1.2

### 一、修正"PID 1 看不到挂载"的误报

```
· 报告里「计划里 146 个槽位，3 个在 PID 1 的挂载表里看不到」是误报：
  DroidSans.ttf、MiSansVF_Overlay.ttf 这些是符号链接（-> Roboto-Regular.ttf 等），
  挂载时是跟随链接挂到真实路径的，报告却拿链接路径去比对
· 现在自检会先把槽位解析成真实路径再比对，不再误报
```

### 二、新增：主题锁屏时钟探测

```
· 诊断报告里会检测 /data/system/theme/clock_*（第三方锁屏时钟样式）
· 检测到就直接说明：这个时钟的数字来自主题资源（图片或主题内字体），
  不读系统字体，模块换的是系统字体，所以换不到它
· 想验证：设置 → 锁屏 → 锁屏时钟样式 换回「默认 / 经典」
```

### 本版重点

```

· 新机型：红魔/努比亚/中兴；荣耀、华为清单；三星统一叫 One UI
```

### 一、导入字体：支持 WOFF / WOFF2 / ZIP

```
· 选文件时可以直接选 .woff / .woff2 / .zip，模块先在手机本地转成 TTF，再走原来的导入流程
· ZIP 里有多个字体、或 ZIP 里再套 WOFF，都能处理
· 转换完全本地完成：不联网、不装 Python、不占额外存储
· 缺空格字符（U+0020）的字体自动补一个空格字形，避免"单词粘在一起"；
  空格宽度为 0 也算缺失，同样会补
· 导入大字体不再卡进度条：读字体信息 / 预热改到后台，成功即刷新列表
   （以前十几 MB 的字体导入后进度条会卡在"正在读取字体信息"）
```

### 二、字体库备份 / 恢复

```
· 一键打包字体库（字体 + 名称 + 设置 + 当前选择）→ Download/fontlib-日期.tar.gz
· 恢复：自动选最新一份，先校验字体文件头，坏文件跳过再写回
· 换机、刷机、折腾坏了都能回滚
```

### 三、系统更新（OTA）后自动适配

```
· 每次开机会比对系统指纹；检测到系统更新
  → 后台重扫槽位 → 按当前选择重新生成计划（不拖慢开机）
· 记录写进 ota.log，界面「通用 → 系统更新后的自动适配记录」可查
```

### 四、机型适配

```
· 新增红魔 / 努比亚 / 中兴（RedMagic OS）识别 + 专用清单
  RedMagicDigit / ZDigit 时钟族、CNZ / HYZhengYuan 中文、ICNDigit 装饰
· 新增荣耀 MagicOS、华为 EMUI/HarmonyOS 清单（HarmonyOS Sans 系列）
· vivo / iQOO 补充 VivoFont / VivoClock
· 三星内部命名统一为 One UI（旧 samsung 清单保留兼容，不会出现没槽位）
· 时钟槽位补全：
    HyperOS 状态栏时钟（MitypeVF）、ColorOS 数字（OSans-Solid-Digits）、
    Flyme 数字（FlymeNumber）都归入「保留锁屏时钟」管辖
· 按 135 份线上报告补了 ColorOS / Flyme / HyperOS 的厂商字体
```

### 五、管理器检测不到更新：已修

```
· 原因：module.prop 的更新地址指向自建 worker，它的 GitHub token 失效后
        一直返回旧版本（v1.3.5），管理器就认为"已是最新"
· 现在：更新地址改为 jsDelivr 直连 update.json；
        开机还会自愈旧版里写死的 worker 地址（用户自己改过的不动）
· 注意：已装 1.5.0 及更早版本的用户，需要先在 UI 里更新一次到本版，
        之后管理器就能正常检测更新
```

### 六、界面与诊断

```
· 修「导入完成但界面不刷新」：导入收尾强制刷新，没拿到列表会自动补刷
· 修「切换 / 开关时界面卡住」：后台执行 + quick 刷新（1.5.0 起）
· 新增「查一下有没有别的字体/主题模块」：冲突检查，含 zygisk 类
· 新增「让所有 App 都能看到字体（一键修）」：
  自动关掉 KernelSU 的「默认卸载模块」（先备份配置；APatch 给指引；Magisk 说明不需要）
· 诊断报告新增「字体配置 XML 可读性」：
  每份配置能不能读、多少字节、family 开/闭数量是否一致，一眼看出"扫不出来"的原因
```

### 注意事项

```
· .otf（CFF 字体）不会做空格修补——只提示，不改文件
· WOFF2 解码依赖 WebView 的 WebAssembly 支持；系统 WebView 太老的机器
  会提示"转换失败"，改用 TTF/OTF 即可
· 字体库备份文件可能很大（字体本身几十 MB），备份前先看存储空间
· 包体积：0.54 MB → 0.71 MB（多了 WOFF2 解码器）
```

## 历史版本

### v1.5.0

> 性能与体验大版本：切换提速（首次 10~20 秒 → 2~3 秒）、界面异步化（不再冻结）、
> 导出字体文件、首次刷入即命中缓存；外加红魔时钟保留、黑名单即改即生效与一批修复。

#### ⚡ 切换与开关提速

- **并行物化**：管理器挂载的 154 个槽位从逐个串行改 10 个一批并行（约 5 秒 → 约 1 秒）；
  生成循环里每槽位 2 次进程（308 个）清零；提交阶段的逐个搬运整段取消。
- **异步应用**：点「应用」/拨开关，界面立刻回话，真正的应用在后台跑（每 0.5 秒问一次进度）——
  等待期间点击、滑动、动画全部正常，不再"冻结"。
- **缓存跨刷入命中**：缓存钥匙改按「影响计划的开关值」计算（不再看配置文件的字节内容），
  首次刷入就全命中，不用再刷两次。
- **自动预热**：安装完成、导入字体、切换、拨开关之后，都会在后台把字体库里所有字体的
  计划提前算好——之后的每一次切换都是命中。

#### ✨ 新功能

- **导出字体文件**：字体库 → 点卡片 → 「导出字体文件（.ttf）」，用模块自带的文件管理器选
  目标文件夹（和导入同一套界面反着用）；重名自动加 (2) (3)，导完核对字节数。
- **红魔/努比亚时钟保留**：RedMagicDigit / ZDigit 系列归入时钟分组，「保留锁屏时钟字体」
  开关现在管得到红魔的锁屏和桌面时钟。
- **黑名单/白名单即改即生效**：保存名单自动重扫一次（原来装好模块之后再填是不生效的）。

#### 🛠 修复

- 「重启后生效」的数字不再误导：新增**开机快照**——拨了开关还没重启时，
  「已生效」保持开机数字不动、「新计划」立刻更新，顶部横幅带上两个数，重启后自动对齐；
  A 切 B 再切 A 这类"实际没变化"的操作不再挂横幅。
- 免重启应用成功后，快照当场追平（横幅立刻消失）。
- 拨几次开关之后切字体变慢（例如 3 秒变 8 秒）：根因是每次拨开关都会把配置文件里的键
  挪到末尾、缓存钥匙按文件内容算就永久换锁——已改按值计算。
- 开关时字体列表偶发变空白：列表读回来是空时不再清屏。
- 提示条时长失控（改几秒都看着一样长）：原因是提示弹出后界面刷新冻结了计时器——
  现在提示在刷新全部结束后弹出，3 秒就是 3 秒。
- 子项目拨开关误报「处理失败」（界面解析正则没跟上耗时字段）。
- 导入进度条如实显示「正在校验并写入字体库（60.4 MB · 这一步最久）」。
- 「修改中」遮罩换成二级菜单同款毛玻璃（半透明 + 背面模糊）。
- 抓日志：ANR 报告完整提取主线程栈（原来截断在守护线程，定不了性）。

### v1.4.8.4

#### 🐞 大 bug 修复：中文合集（.ttc）从来没被替换过

`ttcwrap.sh` 里写字节的格式写成了 `'\\%03o'`（多一个反斜杠）。
shell 把 `\\` 当**字面反斜杠**，于是输出的是文本 `\101\102…` 而不是字节 →
表目录长度永远对不上 → `ttc_wrap` 一直返回 1、产物 0 字节。

**影响**：所有靠 `.ttc` 合集出中文的机型（三星、部分魅族/一加），
中文兜底字体**从来没有真正换过** —— 诊断报告里的 `via=wrapfail` 就是它。

### v1.4.8.3

#### 🐞 修「魅族上什么都替换不了」（槽位计划变成 0 个）

**真机现场**（MEIZU 20 Pro / Flyme / KernelSU）：

```
[3/4] 扫描与槽位
- 槽位计划：0 个，其中中文合集槽位 0 个
上次选择：builtin_flair → 没找到可替换的槽位（范围: all）
→ 已设为「无字体」
```

**原因**：上一版为了防魅族闪退，让 Flyme **完全不做本机扫描**，只用机型清单；
而机型清单里没有 MEIZU 20 Pro 的条目 → 一个槽位都没有 → 装上也白装。

**已修**：

- Flyme **恢复本机扫描**，但**只扫 `/system` 下的字体目录**
- `/product`、`/vendor`、`/my_product`、`/my_stock` 等厂商分区**一律不碰**
  （Flyme 的 UI 字体就在这些分区里，替换它们会引发闪退/跳转失败）
- 厂商字体名单（SFPro / SFDIN / DINPro / MyriadPro…）继续排除，作为第二层保险

升级后会重扫一次（扫描印记 14083）。这一版对非魅族设备无行为变化。
